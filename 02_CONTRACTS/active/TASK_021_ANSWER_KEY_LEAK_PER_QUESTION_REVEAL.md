# 1. High-Density Distilled Objective
`server-lib/questions.ts` and `server-lib/training-questions.ts` `.select('*')` on `static_questions` with zero auth and ship `correct_option` for **every** question the moment a quiz loads — before the user answers anything. The Arena is a **per-question lock-and-reveal** format (20s per-question timer; a question's answer/explanation should only surface once that specific question locks — `src/components/Arena.tsx:567` `questionIsLocked` gate), so the fix is not "strip the column" alone: it is moving the correct-answer reveal from the bulk fetch into a per-question, on-lock authenticated call. There is also a **bundled static fallback** (`src/components/Arena.tsx:419-428`, sourced from `staticQuestionsData`) that ships `correct_option` inside the JS bundle itself with zero network request — this must be scrubbed too, or the whole fix is theater. Grading is already fully server-authoritative and untouched by this contract (`server-lib/submit-quiz.ts:128-158` re-fetches `correct_option` from the DB and never trusts client-supplied values) — do not modify `submit-quiz.ts`'s grading logic.

**Named residual risk, do not try to fully close it in this contract:** moving the reveal to an on-lock call to `/api/explanation` narrows the attack from "read the entire answer key at page load" to "a client could still call the reveal endpoint for an unlocked question id before actually answering it," because there is no server-side per-question session-lock state today (only the final `quiz_sessions` row inserted at submit time). Closing that fully requires server-tracked per-question lock state, which is out of scope here — call it out explicitly in the receipt as a known follow-up, do not claim it is fully solved.
